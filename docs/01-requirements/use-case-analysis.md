# 用例分析

## 1. 角色分析

| 编号 | 角色 | 所属范围 | 职责与目标 |
| --- | --- | --- | --- |
| ACT-01 | 用户 | 城市居民 | 注册登录、上报模拟绿色出行、查看减排量和积分、兑换商品 |
| ACT-02 | 商户 | 积分商城供应方 | 提供商品、维护可兑换库存、处理兑换订单 |
| ACT-03 | 运营管理员 | 平台运营方 | 配置碳核算规则、管理用户和商品、处理异常、查看统计 |

MVP 中商户不拥有独立登录端，商户相关操作暂由运营管理员代为完成；领域模型保留 `Merchant` 实体。

## 4. 关键用例详细说明

### 4.1 UC-04 上报模拟行程

| 项目 | 内容 |
| --- | --- |
| 主要参与者 | 用户 |
| 优先级 | P0 |
| 目标 | 保存一条绿色出行记录，计算并发放本次碳积分 |
| 触发条件 | 用户提交一条模拟行程 |
| 前置条件 | 用户已登录且账户处于启用状态 |
| 后置条件 | 行程保存成功；规则快照保存；积分流水生成；账户余额增加 |

主成功场景：

1. 用户选择出行方式，填写里程、起点、终点和起止时间。
2. 系统校验必填项、里程范围和时间顺序。
3. 系统根据提交时间和出行方式查找当前生效的碳核算规则。
4. 系统计算基准排放、实际排放、碳减排量和本次积分。
5. 系统保存行程、规则版本和计算结果快照。
6. 系统使用行程编号作为幂等业务键，创建积分发放流水。
7. 系统在同一事务内更新积分余额。
8. 系统返回行程结果、减排明细和新余额。

异常与替代流：

- 输入不合法：拒绝提交并返回具体字段错误。
- 账户已停用：拒绝提交。
- 当前出行方式没有生效规则：拒绝发放积分，不保存半成品记录。
- 行程编号已处理：返回已有结果，不重复发放积分。
- 保存流水或更新余额失败：事务回滚，不留下部分数据。

业务规则：

- 支持 `BUS`、`SUBWAY`、`BIKE`、`WALK` 四种方式。
- 模拟里程必须大于 0，课程原型初设上限 200 公里，上限配置化。
- 起止时间必须有效，结束时间不得早于开始时间。
- 每条行程必须保存核算规则版本和因子快照。

### 4.2 UC-11 兑换积分商品

| 项目 | 内容 |
| --- | --- |
| 主要参与者 | 用户 |
| 优先级 | P0 |
| 目标 | 扣减积分和库存，生成兑换订单 |
| 触发条件 | 用户确认兑换某个商品 |
| 前置条件 | 用户已登录，商品已上架，库存大于零，余额充足 |
| 后置条件 | 积分余额、商品库存、积分流水和兑换订单保持一致 |

主成功场景：

1. 用户选择商品和兑换数量，并提交兑换请求。
2. 系统校验请求号，避免重复提交。
3. 系统读取商品状态、库存和所需积分。
4. 系统校验余额与库存是否满足兑换数量。
5. 系统原子扣减积分和库存。
6. 系统创建兑换订单和积分扣减流水。
7. 系统返回订单号和最新余额。

异常与替代流：

- 余额不足：返回失败，不改变余额和库存。
- 库存不足：返回失败，不改变余额和库存。
- 商品已下架：拒绝兑换。
- 同一请求号重复到达：返回第一次处理结果，不重复扣减。
- 任一步骤失败：整个事务回滚。

业务规则：

- 积分不可提现、不可转让。
- 兑换订单创建后立即扣减积分和库存。
- 订单状态只允许按 `CREATED → FULFILLED` 或 `CREATED → CANCELLED` 流转。
- 取消订单是否返还积分和库存必须在迭代评审时明确；MVP 默认仅允许未履约订单取消并冲正。

### 4.3 UC-09 配置碳核算规则

| 项目 | 内容 |
| --- | --- |
| 主要参与者 | 运营管理员 |
| 优先级 | P0 |
| 目标 | 新增或更新可追溯的碳核算规则 |
| 触发条件 | 运营管理员提交规则变更 |
| 前置条件 | 管理员已登录并具有规则管理权限 |
| 后置条件 | 新规则保存、版本唯一、生效时间明确，历史行程结果不变 |

主成功场景：

1. 管理员选择出行方式和基准交通方式。
2. 管理员填写基准排放因子、实际排放因子、积分系数和生效时间。
3. 系统校验数值非负、生效时间合法，并与同方式规则区间不冲突。
4. 系统创建新的规则版本。
5. 系统在生效时间到达后使用新版本；历史行程继续引用旧版本快照。

异常与替代流：

- 数值为负或缺少必填项：拒绝保存。
- 生效区间冲突：要求管理员调整时间或明确结束旧规则。
- 规则已存在且不允许修改：只能创建新版本，不能覆盖历史版本。
