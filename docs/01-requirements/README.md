## 3. 项目概述

### 3.1 项目背景

城市居民在选择公交、地铁、骑行和步行等绿色出行方式时，缺少可量化的减排反馈和持续激励机制。本项目模拟城市绿色出行数据的采集过程，将出行里程和交通方式转换为可解释的碳减排量，并通过不可提现的积分和积分商城形成正向激励。

### 3.2 项目目标

系统面向城市通勤用户、入驻商户和平台运营人员，提供以下核心能力：

1. 用户登记模拟出行记录，并查看个人的碳减排结果。
2. 系统依据可配置、可追溯的规则计算碳减排量和积分。
3. 用户使用积分在商城兑换商品，并查看兑换记录。
4. 运营人员配置规则、维护商品库存和处理兑换订单。
5. 系统保证同一行程不重复发放积分、余额不为负、库存不超卖。

### 3.3 系统定位

“碳中和”是本项目的主题背景。系统实现的是绿色出行的减排激励，不提供碳中和认证、碳资产登记或碳交易服务。

## 4. 参与角色与利益诉求

| 角色 | 主要目标 | 关注点 |
| --- | --- | --- |
| 用户 | 上报绿色出行、查看减排成果、兑换商品 | 操作简单、计算透明、积分准确 |
| 商户 | 提供兑换商品并履行订单 | 商品库存准确、兑换订单可追踪 |
| 运营管理员 | 维护规则和平台运营 | 规则可控、数据可审计、异常可处理 |

商户在 MVP 中不单独建设登录端。商品及订单由运营管理员代为维护，但领域模型保留商户归属，便于后续扩展。

## 5. MVP 范围

### 5.1 范围内

- 用户注册、登录和个人资料查看。
- 公交、地铁、骑行、步行四类模拟出行记录。
- 基于基准交通方式的可配置碳减排计算。
- 积分账户、不可修改的积分流水和积分余额查询。
- 商品浏览、积分兑换、库存扣减和兑换订单。
- 运营人员配置碳核算规则、维护商品和处理订单。
- 基础运营统计与关键业务操作审计。
- 行程、积分、库存和订单的一致性测试。

### 5.2 范围外

- 真实 GPS、地图路径规划和实时公交接口。
- 真实交通卡、支付、退款、提现和现金结算。
- 区块链存证、碳信用登记或碳交易。
- 商户独立门户、复杂物流和多仓库管理。
- AI 路线推荐、社交排行榜和复杂游戏化玩法。
- 对用户上报数据的真实性和身份进行线下核验。

## 6. 关键业务假设

1. 行程数据和里程由用户模拟填写，系统只做格式、范围、时间和重复性校验。
2. 减排基准初设为“同等里程的私人燃油小汽车单人出行”；该基准必须配置化并在报告中注明为模拟假设。
3. 碳排放因子和积分系数均属于规则配置，不在代码中硬编码。
4. 积分不可提现、不可转让，MVP 中不设置过期规则。
5. 兑换订单创建后，积分和库存立即扣减；已履约订单不自动回滚。
6. 系统不宣称计算结果具有官方碳核算效力。

## 7. MVP 验收标准

系统至少能够完成以下端到端场景：

1. 用户登录后上报一条公交出行记录，系统显示里程、基准排放、实际排放、碳减排量和本次积分。
2. 用户重复提交同一条行程时，不重复发放积分。
3. 用户选择商品兑换，余额和库存充足时，积分余额减少、库存减少、积分流水和兑换订单同时生成。
4. 余额不足或库存不足时，兑换失败，积分、库存和订单均不发生部分变更。
5. 管理员修改碳核算规则后，历史行程的减排量和积分结果保持不变。
6. 普通用户不能访问管理员接口或修改他人的数据。
